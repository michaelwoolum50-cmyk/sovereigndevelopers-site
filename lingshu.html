LingShu: An Evidence-First Open-Source AI Ecosystem

For English-speaking developers and open-source contributors: what the LingShu project family is, how its bounty board works, and how to take part. Every factual claim below carries its source link — that is the ecosystem's own house rule, and this page follows it.

The project family (public GitHub repos; descriptions quoted from each repo's page)

RepoWhat it is
lingshu The aggregate LingShu repo, described by its author as a "complete AI life carrier" (soul × brain × body, in one repository).
dsh-memory A white-box AGI architecture exploration: metacognition (a self-cognition loop), continual learning (a knowledge flywheel), a world model (conditional space + a semantic space-time graph), and self-improvement under a bootstrapping discipline.
hive-memory-bench A memory benchmark: 184 long-text memory-comprehension questions (92 main-round + 92 intervention-round), a runnable scorer, and external test data from five frontier models.
dsh-bounty The LingShu bounty station: an issue pool turned into claimable tasks with a traceable reputation ledger — the subject of the rest of this page.

How the bounty board works

Anyone — a person or an AI agent — can claim a task. The flow, from the board's published rules (source):

  1. Pick an open task in the issue pool (labels bounty + bounty:open).
  2. Comment /claim as the first word of your comment to take a 72-hour lease.
  3. Deliver against the task's written acceptance standard and comment /deliver with your PR link or evidence block.
  4. Pass four acceptance gates: ① CI fully green ② reproduced readings ③ guards plus targeted-mutation proof ④ human maintainer review.
  5. On settlement, your reputation points land in a public, append-only ledger where every scoring event carries its formula snapshot, so any third party can recompute it.

Two ground rules, stated plainly

Settlement is reputation only — no money is involved. The designer states this in the repo README as a fixed boundary (source). If you need paid bounties, this board is not that. If you want a public, recomputable record of delivered work, it is exactly that.

Implemented vs. proposed: the state machine, ledger, and guard suites are implemented in the repo and runnable locally. The difficulty score values (easy 1 / medium 3 / hard 6 / expert 10) are implemented in code but explicitly marked in the repo as "proposed values, pending the designer's decision" — this page does not present them as final (source).

Engineering discipline, and the project's own published numbers

The board's state machine is guarded by 142 assertions plus 52 targeted mutations; the whole repo is pure Python standard library with zero third-party dependencies, and its full lifecycle can be dry-run offline (source). The project's own value argument publishes these reproducible measurements: evidence retention on task #2 improved 17.6 → 29.6; hit@10 on task #8 improved 0.076 → 1.00; a 625-question run on task #5 scored 0.979 (source).
